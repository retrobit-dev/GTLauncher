# GTLauncher MatePad Mini preview

The browser preview places a responsive 16:10 sky inside a landscape tablet-shaped frame. The rounded bezel and upper-left punch-hole are illustrative only; the preview does not claim physical-size or DPI accuracy. The rendered homescreen canvas has no visible text, icons, widgets, or controls. The browser adds weather-mode and World controls below the tablet; they are not part of the Android homescreen. The World manager creates, opens, edits and deletes browser-local worlds derived from Base World, with a name, optional notes and island tint. It offers built-in Base World, preserves existing user-created worlds including Home, and stores custom worlds in localStorage on this browser/device only. Impor JSON validates versions 1–6, confirms replacement by ID and rejects older files that would erase unsupported object data. The Ekspor action downloads a versioned JSON file; Ekspor QR additionally downloads a PNG containing the same world data for image-only chat uploads (it is not automatic upload and the QR is not the Android import file). The QR is generated locally, may not fit if world data grows, and contains readable world information; Android can import it via World in the app drawer, save or update a local copy by stable ID and apply its island tint. The version 4 world schema carries one optional character object with its tile, scale and facing; the preview Edit mode supports selecting, dragging and pinch-scaling the character for the active custom world, with a non-gesture settings alternative and per-world undo/redo history for the current browser tab. A Home world starts with a 3×3 house at A1–C3. The house is selectable, draggable, scalable, rotatable and included in version 6 exports; larger-than-default visuals can overhang its logical footprint. Android version 6 import/render code has not been tested on a device. The reusable object catalogue and multiple instances are not yet implemented. This is not automatic synchronisation. A reference-derived character can be placed at the centre of any tile and scaled independently per world; it has a subtle anchored idle animation and is included in version 4 exports for Android.

## Dimetric projection and game look

The island uses a fixed 45° azimuth and 25° elevation above the horizon in both renderers. A 28-unit tile width projects to about 11.8 units of vertical ground depth (a 2.37:1 top-face ratio); the grid axes remain symmetric, with a screen diagonal of about 22.9°. The 9×9 grid uses logical columns A–I and rows 1–9 (row 1 at the top, row 9 at the bottom); coordinate names are internal and are not drawn over the homescreen. Before dimetric projection, columns advance left-to-right and rows top-to-bottom. The diamond compass frame is rotated 45° so the grid axes are cardinal: one row of tiles is a parallel of latitude running east–west and one column of tiles is a meridian of longitude running north–south. On each diamond tile, the top/right/bottom/left corners are northwest/northeast/southeast/southwest; the upper-right/lower-right/lower-left/upper-left edges are north/east/south/west. The camera therefore faces northwest, and device headings are shifted by 45° so sky bearings stay on real compass directions. Langit Matahari is the name for the full 9×9 reference lattice that hangs above the plate (both sky lattices are currently hidden, not removed): the plate's own silhouette at the plate's own size, with the same tile pitch and the same rounded cells, drawn as one flat dark ink (#0b1420) at 0.38 alpha, with the boundary at 0.62. A second lattice with the same geometry, Langit Awan, is white (#ffffff) and sits 50 scene units lower (lift 50) and is shifted 10 scene units along the projected westward grid axis and is intended as the future reference for cloud movement. In live weather and all demos, the Sun follows a projected arc on Langit Matahari and reaches E5 at solar transit; at the current lift most of its disc at the peak is above the screen. Clouds move on Langit Awan along the cardinal grid axis nearest the downwind bearing. Langit Matahari is shifted 20 scene units along the same westward axis. Both lattices retain the tile pitch when displayed; When enabled, Langit Matahari is drawn last over Langit Awan where their projections overlap. See [Base World](../BASE_WORLD.md) for the shared baseline and the rules still awaiting implementation. Every line is a tile seam, which is why the lattice is addressed in the projection's own (column, row) coordinates: integers land on tile centres, so a seam sits at a half value (column = 1.5 is the line between columns B and C). The plate is the diamond |a| + |b| = 9 with a = column − row and b = column + row − 8, so each seam runs from −0.5 to 8.5 along the other axis; deriving the lines from the diamond's corners instead put them half a tile off every seam. No labels are drawn. Three details are load-bearing. The ink is clipped 1.5 units inside the silhouette, because antialiasing on the clip boundary bled a fringe onto the grass band below the front edge. The joins are round, because the boundary's four vertices turn by about 53° and a miter join there shoots a spike outside the plate; that spike was the only ink that escaped. And the seams are 0.5 scene units, exactly one device pixel at RENDER_SCALE 2, so they stay on the art grid. Langit Matahari is lifted 100 scene units clear of the plate and is drawn after the cloud-shade pass, so a drifting cloud's shadow does not dim it. It carries its own silhouette clip instead of borrowing the plate's: clipping to the plate as well sliced the top off the lifted lattice. Measured at 50, the lift moved the ink exactly 100 device pixels up (50 scene units at RENDER_SCALE 2) and changed nothing else — the box stayed 493×204 device pixels and the ink count stayed 9,275. In an earlier measurement at 75 the top corner of the lattice reaches y = −1 and the frame edge cuts it: 22 device pixels touch the top row and about 990 pixels of ink are lost (9,275 down to 8,285). 53 is the highest lift that keeps the whole lattice on screen, so 100 deliberately extends beyond the screen rather than an accident. Measured before the lift, with the frame toggled on and off: 9,274 device pixels changed, all of them on the plate surface, and the lattice held 50:1 contrast on noon grass, 22:1 at dusk and 18:1 at night. A single cross of the two cardinal axes was drawn earlier and then removed; Langit Matahari replaces it. Reducing tile width from 36 to 28 scene units keeps the surface footprint about 252×106.5 units while adding tiles. At the illustrative 250 m per tile scale, the 9×9 patch represents 2.25 km per side. The rounded grass grid alternates Soft Fern (#A8C795) and Fern Sage (#98BA87) with reduced contrast and a soft mid-green underlay instead of dark internal seams; the 8-unit grass band sits above a continuous warm-brown soil body with a 16-unit exposed band and a 4-unit inset per side. The whole island is raised 10 scene units (bottom margin 8 to 18 units), leaving visible sky beneath the unchanged terrain slab. Camera controls remain absent from the preview. For a stronger game look, the most coherent direction is to retain this consistent dimetric grid for the island and future world props, while keeping the sky gradient, rain, fog, and lightning as atmospheric screen-space effects rather than forcing them onto the grid.

## Live sky

The preview uses the browser's current time and, when the browser grants geolocation, the device's coordinates. If geolocation is unavailable or denied, it uses Rembang, Central Java (`-6.7097, 111.3476`). Coordinates are sent to Open-Meteo to request current weather; the preview refreshes about every 30 minutes. The live label reports whether it is using the device location or the Rembang fallback and shows the last fetched cloud-cover percentage; before the first successful fetch it says the weather data has not arrived. If a request fails, it keeps the most recently received conditions for the current page session and continues rendering the sky from the local time.

Both renderers draw the same sky objects: a Sun disc with a breathing halo, a phased Moon once the Sun is down, and layered cloud sprites. The time/weather-adaptive sky gradient and island lighting remain, as do non-object weather effects such as rain, fog, and lightning. Stars are the one sky layer that stays removed.

## Model and approximations

The notes below describe how the visible sky objects are drawn: the Sun and Moon discs, their shared halo, and the cloud sprite layer.

- The old sky objects were removed from both renderers rather than just disabled: the pixel sun disc, rays, bevel, pulse glow, phased moon, star field and horizon glow are gone from the code. `sunPosition()` is retained because its altitude and azimuth still drive the sky gradient and the island lighting. The replacement sun is a plain pixel disc with no face: a full 10.5-unit circle with no rays, outline or facets, filled with a soft two-colour vertical gradient that is intentionally bright, near-white cream at the top into golden yellow at the bottom, with no quantisation steps. A halo of 14 stacked faint discs surrounds it: the lower the sun, the wider and flatter the glow (longer atmospheric path), and the higher the sun, the tighter and rounder it gets, so the glow shape follows the current latitude, longitude and solar position. The halo also breathes, with the discs sliding outward and back on a slow 1.15 rad/s cycle so it reads as alive rather than a static ring. The moon reuses the identical construction: one disc with the same two-colour vertical gradient in a cooler palette (#F4F7FB to #B9C6DA), the same stacked halo, and the same elevation-driven shape. Only the phase mask differs - the terminator is projected as an ellipse, so 100% illumination is a full disc, 50% a straight terminator through the centre, and 20% a thin crescent, driven by the real Sun-Moon elongation. The lit limb follows waxing/waning and flips for the southern hemisphere, and the moon position uses the same simplified Keplerian elements as Android's SkyMath.moon. The moon is only drawn once the sun has dropped below -2 degrees altitude, fading in across 4 degrees, so no pale crescent competes with the sun in the daytime sky. Its position follows the device clock: bodies follow a gently tilted arc that matches the diamond frame: they start slightly lower on the eastern right side and finish slightly higher on the western left side, with a shallow 9-unit tilt so the sun still sinks toward the horizon instead of setting high in the sky. The screen column comes from the body's hour angle, its progress along that arc, while altitude sets the height in the celestial band; alpha ramps linearly from altitude -1 to +3 and it is hidden below that. The palette warms near the horizon and dulls by 40% under heavy cloud. The sun draws behind the island and only within the upper half of the screen. The Sun uses a low-precision NOAA/Meeus-style apparent solar longitude and Greenwich sidereal-time conversion. Atmospheric refraction and topocentric solar parallax are omitted. The Moon uses simplified Keplerian orbital elements rather than the full lunar perturbation series and topocentric parallax. Bright-star J2000 coordinates are precessed with the Meeus/IAU 1976 model; proper motion, aberration, and nutation are omitted. The Moon's pixel-art limb, glow, warm/cool facet colors, and star twinkle remain artistic effects; its illumination-driven phase mask is unchanged. The Sun keeps its upper-edge path and glow, with a low-poly beveled disc and short rays but no face. Stars remain small astronomical pixel points.
- Clouds are raster sprites traced from the reference art, with at least one cloud at 0% cover and up to four at 82% or more. Their width and height, and those of their shadows, are two thirds of their previous size. Their opacity is 0.55. Their centres travel on Langit Awan along the cardinal axis nearest the downwind direction, with 5° hysteresis beyond each 45° boundary, a 3 km/h calm threshold, wind gain 0.05 and a speed cap of 4.2 scene units per second. Positions wrap across the 9×9 coordinate range. Shadows on the island are smaller copies of the same sprites at constant scale 0.78: each centre is the intersection of the light-to-cloud ray with the island plane or its visual extension outside the island. A cloud whose projected centre is above the Sun is drawn before it; one below is drawn in front. At night the Moon provides the projection; if the Moon is below the horizon its virtual position is used to keep shadows visible. The Moon follows the same E5 arc as the Sun. Shadow opacity follows the existing weather and day/night lighting. The old arc, Sun-clearance restriction and heuristic island shadow placement no longer drive cloud placement.
- The island body's cast shadow is independent of cloud projection: it remains fixed directly below the island with constant 1.55× geometry and colour. Its alpha is adjusted to maintain contrast as the sky changes. The 9×9 island grid represents 250 m per tile as an illustrative scale, not a surveyed location. Its logical coordinates are columns A–I and rows 1–9. The 9×9 surface uses rounded dimetric tiles with visible, softly shaded front faces and a low-contrast checkerboard pattern. Tile tops remain solid colors; when the Sun is above the horizon, each entire tile receives only a subtle, uniform Pale Moss tint, attenuated by cloud cover. No directional gradient is drawn inside grass tiles, and the Sun remains visible when above the horizon. The exposed sides of the perimeter tiles meet edge-to-edge without gaps through the full 8-unit grass band, preserving each tile's fern hue, and meet the inset ledge over one continuous warm-brown soil slab: the body is inset 4 scene units per side (about 97% of the grassy top width) and has no internal soil-grid seams. Alternating tile tops use Soft Fern (#A8C795) and Fern Sage (#98BA87), over a Muted Pine (#5A7365) grass base; internal seams use a subtle mid-green underlay rather than a dark outline. Pale Moss (#B6D0A1) is reserved for direct sunlight, and the tones remain adaptive to time and weather. The 24-unit side wall has an 8-unit grass band above 16 units of exposed soil. Pixel flecks and wind-swaying blades are removed to keep the island geometry-only; no crops, trees, or animals are added at this stage. The island shadow remains a stylization rather than a full lighting simulation. The old character sprite and its shadow have been removed from the renderer; the next character design will be created from scratch. The same horizontal-surface projector can still clip to future objects by footprint and elevation.
- The island palette remains adaptive to solar altitude and weather. Cloud shadow projection was removed along with the simulated cloud field, so the island shows only its own cast shadow. Liquid-rain particles still follow weather codes/data; fog and lightning remain weather effects, and precipitation can fall through the full scene. Weather remains the latest provider snapshot, so it may not be sampled at exactly the same instant as the astronomical frame. GPS accuracy, weather coverage, and sensor calibration remain approximate; no forecast accuracy beyond provider data is implied.

The button below the tablet cycles through Live (Open-Meteo), sunny day, overcast, rain, storm, and dusk/night. Demo modes only override preview visuals and synthetic sky time; clicking the control does not make another weather request, and returning to Live restores the latest fetched conditions. A browser location prompt may appear. Location is optional; denying it selects the Rembang fallback. The preview does not store coordinates or weather data beyond the current page session. It does not ask for an API key.

## Run locally

```sh
python3 -m http.server 4173 --bind 0.0.0.0 --directory preview
```

Geolocation generally requires HTTPS or localhost. The weather request is made directly from the browser to Open-Meteo. The sea was removed. It went through several shapes -- a band across the frame, a diamond the shape of the plate, a widened diamond that reached the frame edges -- and was finally cut entirely: it competed with the island for attention, it forced every ground shadow to be clipped to its outline, and at the depths needed to read as water below a floating plate it kept running off the bottom of the frame. What is left under the island is the same sky the rest of the frame shows, so the plate simply hangs in it. With the water gone the plate's cast shadow lands on the ground again as a single diamond tucked close under the plate, and cloud ground shadows no longer need a clip because there is no surface outline for them to spill outside of.
